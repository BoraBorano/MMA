## 4. D6 구현 상세 — 감면 내용 개행 보존

**현행**

- 변환: `benefitDescription`에 `normalizeWhitespace` 적용 → 탭·연속 공백 정리 + **개행 소실**
- 상세 화면: 감면 내용 `dd`에 `whitespace-pre-line` **없음** (비고에만 있음)
- 목록 화면: `line-clamp-3`, `whitespace-pre-line` 없음

**문제** — `normalizeNote`처럼 trim만 적용하면 개행은 살아나지만 연속 공백도 그대로 남습니다. 실제 북부 데이터에 `무료  , 양주시 거주자`처럼 이중 공백이 있어 화면에 그대로 노출됩니다.

**제안 — 새 함수 도입**

```ts
/**
 * 여러 줄 원문 보존용. 개행은 유지하되 줄 단위로 공백만 정리한다.
 * 감면 내용처럼 원문 구조가 의미를 갖는 필드에 사용한다.
 */
export function normalizeMultilineText(value: string): string {
  return value
    .replace(/\r\n?/g, "\n")           // 개행 표기 통일
    .split("\n")
    .map((line) => line.replace(/\t/g, " ").replace(/ {2,}/g, " ").trimEnd())
    .join("\n")
    .replace(/\n{3,}/g, "\n\n")        // 빈 줄 과다 축약
    .trim();
}
```

**변경 범위**

| 대상 | 변경 |
|---|---|
| `src/lib/dataConvert/transforms.ts` | `normalizeMultilineText` 추가 + 단위 테스트 |
| `scripts/convert-data.ts` | `benefitDescription`에 `normalizeWhitespace` → `normalizeMultilineText` |
| `src/components/facility/FacilityDescriptionList.tsx` | 감면 내용 `dd`에 `whitespace-pre-line` 추가 |
| `src/components/facility/FacilityList.tsx` | **변경 없음** — `whitespace-pre-line`이 없어 목록에서는 개행이 공백으로 렌더됨(의도된 동작). `line-clamp-3` 유지 |

**주의 — 남부 데이터에도 적용됩니다**
남부 433건의 감면 내용에 개행이 있었다면 지금은 공백으로 합쳐져 있고, 변경 후 되살아납니다. 변환 전후 `facilities.json` diff로 **남부 영향 건수를 반드시 확인**하고, 의도한 변화인지 판단해야 합니다. 예상하지 못한 대량 diff가 나오면 D6을 북부 소스에만 한정 적용하는 방안으로 후퇴합니다.
