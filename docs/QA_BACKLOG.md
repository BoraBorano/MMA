## D-01. 죽은 홈페이지 URL — n-003 소노휴 양평 `[담당자 판단 필요]`

- **발견**: 2026-08-02 경기북부 데이터 배포 후 실기기 검수
- **증상**: 상세 화면의 "홈페이지 보기" 버튼을 누르면 연결 실패
- **원인**: 원본 엑셀의 홈페이지 값 `www.daemyungresort.com`(대명리조트) 도메인이 살아 있지 않다
  - `https://` — 인증서 공통이름 불일치 (`NET::ERR_CERT_COMMON_NAME_INVALID`). 응답하는 인증서는 Akamai 기본 인증서로 해당 도메인이 altname에 없다
  - `http://` — 리다이렉트 없이 **400** 응답
  - 즉 스킴 문제가 아니라 도메인 자체가 서비스되지 않는 상태다 (운영사가 "소노호텔앤리조트"로 바뀌면서 `sonohotelsresorts.com`으로 이전한 것으로 보인다)
- **영향 범위**: 예우시설 491건 중 홈페이지 URL 보유는 86건. 그중 실동작을 확인한 것은 표본 몇 건뿐이라 **다른 건도 죽어 있을 수 있다**

### 선택지

| 안 | 내용 | 고려점 |
|---|---|---|
| ① URL 제거 | 해당 건의 홈페이지 값을 비워 버튼을 미노출 | 설계 원칙(추정·보완 금지)에 어긋나지 않는다. 사용자는 깨진 링크 대신 아무것도 보지 않는다 |
| ② 새 도메인으로 교체 | `sonohotelsresorts.com` 등으로 수정 | **원본에 없는 값을 넣는 것**이므로 담당자 승인이 필요하다. 원본 갱신 시 되돌아갈 수 있어 원본 엑셀도 같이 고쳐야 한다 |
| ③ 그대로 둔다 | 원본 충실성 우선 | 사용자가 깨진 링크를 경험한다 |

담당자 의견은 **①에 가깝다**(2026-08-02, "홈페이지 주소 미노출로 수정 여부 고려"). 다만 아래 D-02를 먼저 돌려 전수 결과를 본 뒤 일괄 판단하는 편이 낫다.

## D-02. 홈페이지 URL 86건 전수 생존 확인 `[미착수]`

D-01이 표본 1건에서 나온 만큼, 나머지도 점검해야 판단 근거가 선다.

- 대상: `homepageUrl !== null`인 86건
- 방법: HTTP 요청으로 최종 응답코드·리다이렉트·인증서 오류를 수집해 표로 정리
- 주의: 응답이 느리거나 봇을 차단하는 기관 사이트가 있어 **실패 = 죽은 링크로 단정하지 않는다.** 후보를 추린 뒤 수동 확인한다
- 산출: 생존/의심/사망 분류표 → D-01 일괄 판단 입력값
